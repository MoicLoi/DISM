## 门禁一：Binary API

```powershell
.\gradlew.bat :core:checkKotlinAbi --console=plain
```

已接入 `:core:check`，所以任何走 `check` / `build` 的 CI 都会执行。

基线：

```text
core/api/jvm/core.api       JVM
core/api/core.klib.api      iosArm64 / iosSimulatorArm64 / js / wasmJs
```

### ✅ klib 覆盖深度问题已修复（成员级）

**当前状态：两个引擎都是成员级。**

```text
JVM core.api      64024 bytes   成员级
core.klib.api     1045 lines    成员级
```

曾经的退化（已修复，记录在此以避免重犯）：

```text
core.klib.api     173 lines     只到类型级（class / interface / enum entry）
```

### 根因：通配符语义用错了

不是 KLib 渲染器不支持成员，是**过滤器把成员滤掉了**。

官方文档（[byNames](https://kotlinlang.org/api/kotlin-gradle-plugin/kotlin-gradle-plugin-api/org.jetbrains.kotlin.gradle.dsl.abi/-abi-filter-set-spec/by-names.html)）的语义：

```text
**   匹配零或多个字符，**含点**
*    匹配零或多个字符，**不含点** —— 用于指定单个类名
```

而原来的写法是 `me.moiclathy.dism.api.*`：

```text
…api.DismCapabilities          ✓ 匹配（* 正好等于一个类名）
…api.DismCapabilities.hashCode ✗ 不匹配（* 跨不过那个点）
```

改成一个 `**` 即可：

```kotlin
"me.moiclathy.dism.api.**"          // 而不是 .*
```

（这九个包都没有子包，所以 `**` 不会顺带拉进别的东西。）

### 修复前后的实测对比

```text
                          修复前        修复后
core.klib.api             173 行        1045 行
core/api/jvm/core.api     47679 bytes   64024 bytes   ← JVM 也在少覆盖成员
```

### 破坏性验证（证明缺口已关）

给 `DismApiVersion` 加一个公开方法 `abiProbeKlib()`，`checkKotlinAbi` 输出：

```text
<<<ABI has changed>>>
--- core/api/core.klib.api          ← 修复前这里不会有输出
+++ core/build/kotlin/abi/core.klib.api
+    final fun abiProbeKlib(): kotlin/String

<<<ABI has changed>>>
--- core/api/jvm/core.api
+++ core/build/kotlin/abi/jvm/core.api
+	public final fun abiProbeKlib ()Ljava/lang/String;
```

两个引擎都报警了，说明非 JVM 目标的成员级变更现在会被抓住。

### 走过的弯路（避免重复）

```text
曾以为：KLib 渲染器只能到类型级
曾以为：exclude-only 可以替代 include
```

`exclude-only` 被实测否定：只排除 `nl.*` 时 klib 从 19560 降到 19435
（仅少 125 行类型声明），成员没被剪掉——因为 exclude 用 `*` 时
同样匹配不到成员。真正的修法自始至终就是「换通配符」。

## 门禁二：依赖可复现性

两层，文件在仓库里就自动生效：

```text
gradle/verification-metadata.xml     sha256 校验，2046 个 artifact
core/gradle.lockfile                 版本锁定
server/gradle.lockfile
app/shared/gradle.lockfile
settings-gradle.lockfile
```

### 两个已知边界

**1. AAPT2 走 trusted-artifact 豁免**
AGP 把它解析进 detached configuration；它不是运行期依赖，也不随库分发。
豁免是窄口径的（一个 group + name）。
不用手写 checksum 是因为手写条目会在重新生成时被静默丢掉——
文件看起来还在，其实已经不覆盖 AAPT2 了。

**2. `--refresh-dependencies` 会失败**
依赖经 Aliyun 镜像解析，强制刷新拿到的元数据可能与基线不一致。
常规构建路径不受影响。

## 公共 API 的变更流程

这条流程在 1.0.0 → 1.1.0 的真实变更上被走通了一次：

```text
1. 改代码（additive：DynamicScheduleFacade.preview）
2. :core:checkKotlinAbi 失败，打印精确 diff
     <<<ABI has changed>>>
     + public abstract fun preview (...)
3. 确认"这次变更是我想要的"
4. 按 SemVer 升 MINOR：DismApiVersion.MINOR = 1
5. 跑 :core:updateKotlinAbi 更新基线
6. 更新断言版本号的契约测试
7. 在 docs 里记录这次变更
```

**不要**为了"让构建变绿"而直接跑 `updateKotlinAbi`。
它回答的是"我接受这次 ABI 变更吗"，不是"怎么消掉这个错误"。

## 关于 iOS

本项目在 Windows 上构建，Kotlin/Native 的 iOS 目标被禁用：

```text
w: Native task 'iosSimulatorArm64Test' is disabled
```

所以 `core/api/core.klib.api` 里的 iosArm64 / iosSimulatorArm64 条目
是从 klib 元数据生成的，**没有在本机编译验证过**。
真正的 iOS 构建验证需要 macOS。这一点不算已通过。
