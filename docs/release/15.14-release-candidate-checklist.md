# 15.14 Release Candidate Checklist

## 这份清单的定位

它区分两件事：

```text
"RC 检查清单"        —— 定义为 1.0.0 之前必须通过的门
"已经通过 RC"        —— 只在这些门全部通过之后才成立
```

不能因为 `API contract ✅` 就宣称 `DISM 1.0.0 RC-ready`。

## Gate 定义

```text
完整 Gradle 工程
      ↓
完整测试矩阵
      ↓
Binary API 检查
      ↓
依赖版本可复现
      ↓
各目标平台 Build
      ↓
文档 / API 对齐
      ↓
只修 Release-blocking bugs
      ↓
API Freeze
      ↓
RC
```


## Binary API 门禁（已接入）

用的是 **Kotlin Gradle Plugin 内置**的 ABI validation，
不是 `kotlinx-binary-compatibility-validator`：

```text
BCV README（0.18.x）:
  "The implementation of new features has been stopped in favor of
   adding them to the experimental binary compatibility validation
   in the Kotlin Gradle plugin."
```

即 BCV 已进入只修关键 bug 的维护状态。本项目 Kotlin 2.4.10 自带该能力，
因此没有新增任何第三方插件依赖。

```text
:core:updateKotlinAbi   生成/更新基线
:core:checkKotlinAbi    校验（已接入 :core:check）
```

基线文件：

```text
core/api/jvm/core.api        JVM 公共 ABI
core/api/core.klib.api      iosArm64 / iosSimulatorArm64 / js / wasmJs
```

**过滤规则**：只 dump 15.x 冻结的九个包，并排除带
`@DismInternalApi` 的声明。不做 include 过滤的话，dump 会是
1.4MB(JVM)+3.1MB(klib)（本模块有约 990 个 `public` 类型），
任何内部重构都会让门禁失败，最后所有人都开始盲跑 `updateKotlinAbi`——
那样门禁就形同虚设了。

**门禁经过验证**：往 `DismFactory` 里加一个 `fun abiProbe(): String`
会让 `checkKotlinAbi` 失败并打印精确 diff：

```text
<<<ABI has changed>>>
+++ core/build/kotlin/abi/jvm/core.api
+	public final fun abiProbe ()Ljava/lang/String;
```

## 依赖可复现性门禁（已接入）

两层：

```text
gradle/verification-metadata.xml     sha256 校验（2046 个 artifact / 1093 个组件）
core/gradle.lockfile                 版本锁定
server/gradle.lockfile
app/shared/gradle.lockfile
settings-gradle.lockfile
```

锁定配在**根脚本**的 `subprojects { dependencyLocking { lockAllConfigurations() } }`，
避免"core 锁了、app 没锁"这种半截状态。

**门禁经过验证**：

```text
篡改一个 sha256
  → 24 artifacts failed verification

删掉一条 jvmCompileClasspath 锁
  → Resolved 'app.cash.sqldelight:jdbc-driver:2.3.2'
    which is not part of the dependency lock state
```

两个边界：

1. **AAPT2 走窄口径 `trusted-artifacts`**（AGP 的 detached configuration，
   既不是运行期依赖也不随库分发）。不用手写 checksum 是因为手写条目
   会在重新生成时被静默丢掉。
2. **`--refresh-dependencies` 会失败**：依赖经 Aliyun 镜像解析，
   强制刷新拿到的元数据可能与基线不一致。常规构建路径不受影响。

## 关于与规格快照的差异

15.14 规格是基于一个**只有 `src/` 的压缩包**写的，
所以它把"完整 Gradle 工程""多平台构建""文档""Example"
都标成了未完成。

本项目的实际工作副本包含完整 Gradle 根工程，
因此这些门在本项目里**已经可以验证并且已经通过**。
状态以实际工作副本中的文件与测试结果为准。
