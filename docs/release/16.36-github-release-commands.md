# GitHub 发布：命令清单

这份文件是发布时的操作手册。里面的每条命令都在本仓库的工作副本上实际执行过，
结果附在命令后面；没跑过的命令会明确标注「未验证」。

对应的发布说明（也就是 GitHub Release 页面正文）在
[16.36-github-release.md](16.36-github-release.md)。

---

## 0. 前置条件

| 项目 | 要求 | 本机实测 |
| --- | --- | --- |
| JDK | 17 以上；AGP 9 需要 17 | OpenJDK 21.0.12.1（Microsoft） |
| Android SDK | `compileSdk = 36` | 由 `local.properties` 的 `sdk.dir` 指定 |
| Gradle | 由 wrapper 自动下载 | 9.1.0 |
| 浏览器 | 只有跑 `*BrowserTest` 才需要 | Chrome Headless 154 |
| WiX Toolset | 只有打 MSI 才需要（3.x） | 未安装，因此默认不出 MSI |
| `gh` CLI | 只有用命令行上传才需要 | 未安装，上传走 Web UI |

> 这台机器上**没有** `pwsh`（PowerShell 7），只有系统自带的
> Windows PowerShell 5.1。所以命令一律写成
> `powershell -ExecutionPolicy Bypass -File ...`。
> 在装了 7.x 的机器上把 `powershell` 换成 `pwsh` 即可，参数一样。

`local.properties` 不进源码包（里面是本机 SDK 路径）。克隆者需要自己建一个：

```properties
sdk.dir=C\:\\androidsdk
```

不打算构建 Android 的话，可以完全不建这个文件。

## 1. 一条命令生成发布包

```powershell
powershell -ExecutionPolicy Bypass -File tools/package-github-release.ps1
```

它会依次做四件事：构建产物 → 打源码 zip → 打各平台产物 → 写 `SHA256SUMS.txt`。

输出目录：

```text
build/github-release/dism-1.5.0/
├── README.md                包内说明
├── COMMANDS.md              本文件
├── RELEASE-NOTES.md         发布说明（= GitHub Release 正文）
├── VERSION.txt              构建时间与版本
├── SHA256SUMS.txt           全部文件的校验和
├── source/
│   └── dism-1.5.0-source.zip
└── artifacts/
    ├── desktop/dism-1.5.0-desktop-windows-x64.zip
    ├── web/dism-1.5.0-web-js.zip
    ├── web/dism-1.5.0-web-wasm.zip
    └── android/dism-1.5.0-debug.apk
```

常用开关：

```powershell
# 产物已经构建过，只重新组装目录（快）
powershell -ExecutionPolicy Bypass -File tools/package-github-release.ps1 -SkipBuild

# 额外尝试 Windows MSI（需要 WiX Toolset 3.x，没有就会只在警告里失败）
powershell -ExecutionPolicy Bypass -File tools/package-github-release.ps1 -TryMsi

# 保留 web 产物的 source map（默认剔除，单个 6MB 量级，对下载者没价值）
powershell -ExecutionPolicy Bypass -File tools/package-github-release.ps1 -IncludeSourceMaps

# 换版本号（默认 1.5.0，与 :core 的 DismApiVersion.STRING 一致）
powershell -ExecutionPolicy Bypass -File tools/package-github-release.ps1 -Version 1.6.0
```

> 版本号只改文件名和 `VERSION.txt`。要让**应用自己**报 1.6.0，
> 还得改 `core/.../api/DismApiVersion.kt`，
> 以及 `app/desktopApp/build.gradle.kts`、`app/androidApp/build.gradle.kts` 里的版本字段。

### 两个刻意为之的细节

```text
zip 条目名用正斜杠          .NET Framework 的 CreateFromDirectory 写反斜杠，
                            在 Linux 上 unzip 会解出一堆名字带 \ 的文件。
                            Web 产物经常部署到 Linux 容器，所以手工写条目名。

条目排序 + 固定时间戳        同样的输入两次打包得到逐字节相同的 zip，
                            SHA256 可复现（源码 zip 已验证两次一致）。
```

```powershell
  :core:packageAndroidMainResources :core:compileTestKotlinJs `
  :core:jsBrowserTest :core:wasmJsBrowserTest `
  :app:shared:compileKotlinJs :app:shared:compileKotlinWasmJs :app:shared:compileAndroidMain `
  :app:desktopApp:compileKotlin `
  :app:androidApp:compileDebugKotlin `
  :app:webApp:compileKotlinJs :app:webApp:compileKotlinWasmJs `
  :server:compileKotlin `
  --console=plain
```

最近一次结果：

```text
:core:jvmTest              271 suites / 1352 tests / 0 failures
:app:shared:jvmTest         12 suites /   74 tests / 0 failures
:core:jsBrowserTest        252 suites / 1294 tests / 0 failures
:core:wasmJsBrowserTest    252 suites / 1294 tests / 0 failures
:core:checkKotlinAbi       PASSED（jvm + klib 两个引擎）
```

`checkKotlinAbi` 会在公共 API 变化时报错。改了 API 且确认是有意为之，才用：

```powershell
.\gradlew.bat :core:updateKotlinAbi
```

### 2.1 依赖校验的干净校验（发布前必跑一次）

```powershell
.\gradlew.bat --stop
.\gradlew.bat help --no-configuration-cache
```

为什么单独来一条：**configuration cache 会把"依赖校验"一起缓存掉**。
配置缓存命中时，classpath 的解析结果直接反序列化出来，校验根本不再执行。
于是 `verification-metadata.xml` 里少记了条目也看不出来——
直到某次改了 build 脚本、缓存失效，才突然报：

```text
Dependency verification failed for configuration 'classpath'
31 artifacts failed verification
```

这次发布就撞上了这个：31 个 buildscript classpath 条目缺失，
平时被配置缓存掩盖着。修法是**在完整任务集上**重写元数据，
然后立刻做一次冷启动校验：

```powershell
.\gradlew.bat <上面那整套任务> --write-locks --write-verification-metadata sha256 --no-configuration-cache
```

⚠ `--write-verification-metadata` 是**有损**操作：只写这次解析到的条目，
没解析到的会被删掉。所以任务集必须覆盖所有日常验证任务，
否则今天补上了 classpath、明天又丢了别的。

### 3.1 打包运行时缺模块（16.36 实际踩到，已修）

桌面安装包做出来之后**必须真的启动一次**。只跑 `:app:desktopApp:run` 不算验证，
因为那条路用的是本机完整 JDK，而安装包用的是 `jlink` 裁过的 runtime。

症状：

```text
双击 exe → 窗口还没画完就退出，退出码 1
stderr: java.lang.NoClassDefFoundError: java/sql/DriverManager
        at app.cash.sqldelight.driver.jdbc.sqlite.ThreadedConnectionManager
```

原因：`jpackage` 用 `jdeps` 推断要带哪些 JDK 模块，而 `jdeps` 看不到反射。
SQLDelight 的 `JdbcSqliteDriver` 是通过 `java.sql.DriverManager` 建连接的，
只在运行时才加载，于是 `java.sql` 根本没进 runtime。

修法（已提交）：

```kotlin
// app/desktopApp/build.gradle.kts
nativeDistributions {
    modules("java.sql", "java.naming", "jdk.unsupported")
}
```

验证方式（两步都要）：

```powershell
# 1. runtime 里确实带了模块
Select-String -Path app\desktopApp\build\compose\binaries\main\app\me.moiclathy.dism\runtime\release -Pattern 'java.sql'
# MODULES="java.base ... java.sql ... jdk.unsupported"

# 2. exe 真的活着（不是"启动了"，是"25 秒后还在"）
#    stdout 出现 DISM.BOOTSTRAP.READY，窗口标题 DISM，~\.dism\dism.db 被写入
```

## 3.5 发布包的自检（做完包之后跑）

```powershell
# 逐字节可复现：连跑两次，除 VERSION.txt（里面是打包时间）外全部一致
powershell -ExecutionPolicy Bypass -File tools/package-github-release.ps1 -SkipBuild

# zip 里必须是正斜杠，否则 Linux 上 unzip 会解出一堆名字带 \ 的文件
# （脚本已保证，下面这条是抽查）
```

实测结果（两次打包）：

```text
source/dism-1.5.0-source.zip                  SHA256 相同
artifacts/desktop/...-desktop-windows-x64.zip SHA256 相同
artifacts/web/...-web-js.zip                  SHA256 相同
artifacts/web/...-web-wasm.zip                SHA256 相同
artifacts/android/...-debug.apk               SHA256 相同
VERSION.txt                                   不同（打包时间，符合预期）
```

### 3.6 源码包自检：解压出来真的能构建

光"打出一个 zip"不算验证。把 source 包解到临时目录、按下载者的处境补一个
`local.properties`，然后跑构建：

```powershell
$dest = Join-Path $env:TEMP 'dism-src-test'
Expand-Archive build\github-release\dism-1.5.0\source\dism-1.5.0-source.zip -DestinationPath $dest
$root = Join-Path $dest 'dism-1.5.0'

# 下载者必须自己建这个文件（包里刻意没有）
Set-Content "$root\local.properties" 'sdk.dir=D\:\\androidsdk'

Push-Location $root
.\gradlew.bat :core:compileKotlinJvm --console=plain --offline
.\gradlew.bat :core:checkKotlinAbi    --console=plain --offline
Pop-Location
```

实测：

```text
:core:compileKotlinJvm   BUILD SUCCESSFUL（3s，2 个任务命中构建缓存）
:core:checkKotlinAbi     BUILD SUCCESSFUL（27s，8 个任务实际执行）
```

`checkKotlinAbi` 是特意挑的：它要重新导出 API 再和包里的
`core/api/jvm/core.api`、`core/api/core.klib.api` 比对，
等于顺带证明源码包里的 API 快照与代码一致。
（注意：两个都用 `--offline`，依赖全部来自本机缓存。
下载者在自己的机器上首次构建需要联网。）

## 4. 本地跑起来

### 桌面

```powershell
# 从源码直接跑
.\gradlew.bat :app:desktopApp:run

# 或跑发布包里的那份（exe 在解压目录根部，不在 bin\ 里）
Expand-Archive build\github-release\dism-1.5.0\artifacts\desktop\dism-1.5.0-desktop-windows-x64.zip -DestinationPath $env:TEMP\dism-desktop -Force
& "$env:TEMP\dism-desktop\dism-1.5.0-desktop\me.moiclathy.dism.exe"
```

数据落在 `~\.dism\`（`dism.db` + `calendar.ics`），删掉这个目录就是恢复到初始状态。

> **这两条路不是同一件事。** `:app:desktopApp:run` 用的是本机完整 JDK，
> 打包出来的那份用的是 `jlink` 裁过的 runtime。
> 缺 `java.sql` 这类"只在运行时才加载"的模块，只有后者会失败——
> 这个坑在 16.36 真的踩到了，见下面「打包运行时缺模块」。

### Web

```powershell
# 开发模式（webpack dev server，热更新）
.\gradlew.bat :app:webApp:jsBrowserDevelopmentRun
# 打开 http://localhost:8080/
```

发布出来的静态文件是纯前端产物，任何静态服务器都能喂：

```powershell
# 需要本机有 Python
cd app\webApp\build\dist\js\productionExecutable
python -m http.server 8080
# 打开 http://localhost:8080/
```

> Web 端的数据在 `localStorage` 里：日历原文与决策历史都能跨刷新存活，
> 但**不同浏览器 / 不同 profile 之间不共享**，也没有导入导出。

#### 发布包里的 Web 产物验证到什么程度

用 Chromium 158 无头加载 `http://127.0.0.1:8099/`（就是解压出来的那份）

```text
服务端        index.html / styles.css / webApp.js / skiko.wasm / 字体 全部 200
DOM           <div style="position: relative"> 那层 Compose 根节点已经挂上
控制台        页面错误 0 条
              只有 favicon.ico 404（站点没有图标，无关）
              与两条 WebGL 调试扩展的 warning（无头环境没有 debug_renderer_info）
```

**没有验证到的**：画面看起来对不对。截图能拿到（`build\web-artifact.png`），
但当前模型没有图像输入能力，看不了。所以只能证明"跑起来了、没报错"，
不能证明"画得对"。这条差距留在文档里，不假装补上了。

### 服务端

`:server` 目前是一个 Ktor Hello 桩（`GET /` 返回一句问候），
没有承载 DISM 的语义，所以**不随发布包分发**。想跑：

```powershell
.\gradlew.bat :server:run
```

## 5. 上传到 GitHub

### 5.1 用 `gh` CLI（本机未安装）

```powershell
# 打 tag（tag 名与发布版本一致）
git tag -a v1.5.0 -m "DISM 1.5.0"
git push origin v1.5.0

# 建 release 并一次传完全部附件
gh release create v1.5.0 `
  build\github-release\dism-1.5.0\source\dism-1.5.0-source.zip `
  build\github-release\dism-1.5.0\artifacts\desktop\dism-1.5.0-desktop-windows-x64.zip `
  build\github-release\dism-1.5.0\artifacts\web\dism-1.5.0-web-js.zip `
  build\github-release\dism-1.5.0\artifacts\web\dism-1.5.0-web-wasm.zip `
  build\github-release\dism-1.5.0\artifacts\android\dism-1.5.0-debug.apk `
  build\github-release\dism-1.5.0\SHA256SUMS.txt `
  --title "DISM 1.5.0" `
  --notes-file build\github-release\dism-1.5.0\RELEASE-NOTES.md
```

### 5.2 用网页（本机走这条）

```text
1. 仓库 → Releases → Draft a new release
2. Tag: v1.5.0（新建）  Target: 发布用的那个 commit
3. Title: DISM 1.5.0
4. 正文：粘贴 RELEASE-NOTES.md 的内容
5. 附件：把上面五个文件逐个拖进去
6. Publish
```

**源码是不是必须上传？** GitHub 会自动生成 `Source code (zip/tar.gz)`。
但那是仓库快照，包含 `.github/` 之类与本产品无关的内容；
`dism-1.5.0-source.zip` 是显式筛过的可编译源码集，两者不冲突，建议都留着。

## 6. 下载者怎么校验

```powershell
# 在放 SHA256SUMS.txt 的目录里
Get-FileHash .\artifacts\desktop\dism-1.5.0-desktop-windows-x64.zip -Algorithm SHA256
# 和 SHA256SUMS.txt 里对应那行比对
```

`SHA256SUMS.txt` 是相对发布包根目录的路径，`sha256sum -c` 也能直接用：

```bash
sha256sum -c SHA256SUMS.txt
```

## 7. 这个包**没有**做的事

写清楚比含糊过去有用：

```text
没有代码签名       没有证书，Windows 首次运行会提示"未知发布者"
没有 MSI           打包需要 WiX Toolset 3.x，本机没装
没有正式签名 APK   debug 包，安装时提示"未知来源"
没有 iOS 产物      iOS 目标在 Windows 上无法构建
没有 server 产物   它还是 Hello 桩
没有自动打 tag     版本号是人的决定
```

这些是限制，不是待办。要做哪一项都需要先解决它缺的那个前提（证书 / WiX / macOS 机器）。
