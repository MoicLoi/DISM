# 无障碍（16.30）

## 为什么先做对比度

无障碍里大部分东西（读屏实测、触摸目标、动态字号）需要
真机或人工验证。**对比度不需要**——它是纯数学：

```text
WCAG 2.1 相对亮度  →  对比度比值
```

所以它可以写成断言，成为**自动门禁**。这是当前能真正
"锁住"的部分，而锁住的东西不会在下次调色时静默退化。

## 对比度门禁

`DismContrastTest` 检查所有前景/背景配对：

```text
浅色与深色主题
  onSurface / surface                    正文
  onSurfaceVariant / surface             次要文字
  onSurfaceVariant / surfaceVariant      卡片上的次要文字
  onPrimaryContainer / primaryContainer  Attention 与反馈横幅
  error / surface                        错误行
  primary / surface                      界面组件（3:1）

阈值（WCAG 2.1 AA）
  正文文字                    4.5 : 1
  大字与界面组件               3.0 : 1
```

当前全部通过。

### 先验证函数，再验证配色

```kotlin
theRatioFunctionFollowsWcag
```

这条测试在写配色断言**之前**先校验对比度函数本身：

```text
黑对白    必须是 21 : 1（最大值）
同色对同色 必须是 1 : 1
中灰对白   必须约 3.95
```

**它不是形式主义**——写这个门禁时它立刻抓到实现里的一个错：

```kotlin
// 错的（少了 sRGB 去 gamma 的偏移与缩放）
c.pow(2.4)

// 对的
((c + 0.055) / 1.055).pow(2.4)
```

错版把中灰对白算成 **4.35** 而不是 3.95，也就是**所有对比度都偏乐观**。
若没有这条自校验，其余 5 条配色断言会带着错误公式全部"通过"——
门禁会放过本该失败的配色。

```text
一个算错的度量函数
  →  所有断言都通过
  →  但没有在检查任何东西
```

## 颜色的单一来源

配色原本在 `DismTheme.kt` 里写死，而门禁也需要那些数字。
两份常量必然漂移：

```text
有人调了主题里的 primary
→ 门禁还在检查**旧**颜色
→ 继续通过，而实际配色已经不合格
```

所以颜色抽到 `DismPalette`（ARGB 常量），主题与门禁都引用它。
漂移在结构上不可能发生。

命名用 Material3 的**角色名**（`onSurfaceVariant`）而不是
描述性名字（`mutedText`）：角色名在换配色后仍然正确，
描述名会开始撒谎。

## 标题语义

```kotlin
Modifier.pageHeading()
```

视觉上什么都不变。变的是无障碍工具看到的结构：

```text
没有 heading()   读屏只能逐行念
有 heading()     可以"跳到下一个标题"
```

这是"看不见但很实用"的一类改进：对健全用户毫无帮助，
对读屏用户是数量级的差别。

六个页面的标题都带上了。目前每页只有一个标题，
价值有限；但它是正确结构——一旦页面出现分节
（Semantic State 的"计数/关系"、History 的"条目/截断提示"），
标题导航会立刻变得有用。

## 导航角标已有无障碍描述

见 [Decision History](decision-history.md#全局可见性导航角标1628)：
角标不只是 `!`，它带一条完整描述，
且**角标与描述必须同时在或同时不在**。

## 无障碍检查顺带照出的一个真 bug

`TodayScreen` 的 `TimelineRow` 收一个 `onClick` 参数，
但**从未**把它接到 `.clickable` 上：

```text
1. onSelectItem 从 App 一路传到 TimelineRow 然后被丢弃
   → 点时间线上的条目没有任何反应
2. 无障碍层面它不可聚焦也不可激活，而调用方以为可以
```

修法**不是**把 `clickable` 接上：目前没有详情页，
接上就是一个点了没反应的按钮——比不接更糟。

所以整条链路被删掉。等真的有了详情页，
再把它作为一个**有行为**的可点击区域加回来。

> 无障碍检查往往能顺带照出"界面承诺了但没兑现"的地方。
> 这次就是：它把一个死参数从"看不出来"变成了"必须处理"。

## 还没做的

```text
读屏实测            需要真机/模拟器与人工操作
动态字号            需要验证 200% 字号下布局不破
键盘导航            需要确认 Tab 顺序与焦点可见性
触摸目标尺寸        Material3 组件自带上限，
                    但自定义可点击区域需要逐个确认
```

这些都需要设备或人工验证，与 Android 侧
"仅有编译验证"的限制是同一个。

## 可复用的做法

```text
能把检查写成纯数学的   →  写成门禁（对比度）
只能人工确认的         →  如实标注为"未验证"，不要假装测过
```
